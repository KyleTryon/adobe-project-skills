# Premiere Pro demo project

A from-scratch Premiere Pro project whose media lives next to it (generated test media plus a public-domain interview clip), so anyone can open it in Premiere with nothing offline. It serves two purposes:

1. **Evidence for the format spec.** `steps/` holds a copy of the project after each single action (table below). Diffing consecutive steps shows exactly which objects that action creates or changes, and the spec cites them as `[O: steps 05→06]`.
2. **Eval fixture.** The finished project is what the skill's evals edit, and what a person opens in Premiere to check an edit.

### Adding a step

Record or generate it, diff it against the step it came from, add its row here, and write what it shows into the spec (or a guide) with a citation. If a command reproduces it, add a case to `tests/premiere-pro/replay_steps.py`. There's no separate notes file: the spec, this table and the tests are the record.

## Recording the steps

1. In Premiere, turn **Auto Save** off (Settings › Auto Save).
2. Create the project here: **File › New › Project**, name `demo`, location this folder (`fixtures/premiere-pro/`).
   To continue an existing recording instead, open the latest file in `steps/` (or a copy of it) and work from that; the working project itself is never committed.
3. After each action, **File › Save a Copy** into `steps/` as `NN-short-name.prproj` (`00-blank.prproj`, `01-import.prproj`, …). Save a Copy leaves you working in `demo.prproj`; Save As would switch files and change the project's own name and paths.
4. One action per copy. If you make a mistake, undo it and save the copy again under the same number.
5. From the repo root, run `python3 -I tools/premiere-pro/scrub_steps.py` to replace your macOS user name in the saved paths (the replay tests fail on an unscrubbed step).
6. Add the step's row to the table above, noting anything not obvious from the name (a setting chosen, a dialog seen).

Saved projects contain absolute paths, including your macOS user name; `tools/premiere-pro/scrub_steps.py` rewrites the user name to `editor` and the repo's location to `/Users/editor/adobe-project-skills`, so nothing shows where the project was saved; `generated/build.sh --local` maps them back for opening in Premiere. The scrubbed steps are committed; `.prin` files (Premiere's search index) and auto-saves are git-ignored.
